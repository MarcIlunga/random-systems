# CR18 (Maurer, *Cryptography Foundations*, Spring 2018) — Random-Systems Formalization Checklist

**Goal.** Formalize every CR18 definition and statement that is a **pure random-systems
fact**, in a **parallel namespace** (`RandomSystems.CR18.*`) that does **not** disturb
the existing `RandomSystems.*` code (depended on elsewhere). Transition the existing code
onto this faithful layer later.

**Scope rule (narrowed 2026-06-07).** *Pure random systems only.* A row is in scope iff
it is directly a fact about random systems — DDS/PDS/behavior, their algebra
(composition, cascade, converters, filters, interfaces), distinguishing advantage /
statistical distance between systems, games as systems-with-MBO, and indistinguishability
(conditional equivalence, the fundamental theorem, switching). **Anything that would more
naturally live in another library is OUT** and we do not deal with it here:
- **Computational problems & reductions** (Ch4 §4.1–4.9: search problems, performance/
  solvers, τ-reductions, RSA/LSB, DL/CDH/DDH, q-clonability, random self-reduction,
  reduction-based hardness amplification) → *reductions library*.
- **Constructive cryptography** (Ch5: resources, specifications, constructions,
  relaxations, protocols, game-relaxation) → *CC library*.
- **Scheme primitives** (Ch2: symmetric cryptosystem, PRG, block cipher, MAC, PKE, TOWP,
  DSS, hash + their security games) → *game-based / scheme library*.
- **Randomness extraction / hashing / info-theory** (Ch6 AUH & CBC bound; Ch7 universal
  hashing, entropy bounds, ROM, SKA) → *extraction / info-theory libraries*.

**Source of truth.** This file. Items checked off only when the Lean statement exists,
builds, and is `sorry`-free (proofs may land incrementally; stated-but-unproven = `[~]`).

## Decisions (locked 2026-06-07)

**D1 — Pure random systems only** (see Scope rule). The "catalogue everything incl.
schemes" decision is *superseded*: schemes, reductions, CC, and hashing/extraction are
out and routed to their own libraries. The OUT items are listed compactly at the end so
nothing is silently lost, but they are **not** formalization targets here.

**D2 — DDS = faithful partial function, finite by default.** `RandomSystems.CR18.DDS`
is the prefix-closed partial function of Def 3.2 — an explicit `dom : Set (List X)`
(prefix-closed, `[] ∉ dom`) plus a `dom`-indexed total responder (equivalently a
`PFun (List X) Y` with the closure law). The current `Fin q → (Fin (i+1) → X) → Y` total
table is **proven the finite specialization** (`dom = nonempty prefixes of length ≤ q`
over `Fintype X`) via an explicit `CR18.DDS ≃ finiteTableDDS`. **[x] B1 done** —
`RandomSystems/CR18/DDS.lean`: `DDS.FinDomain`, `DDS.finiteTableDDS`, `DDS.FiniteTableDDS`,
and `DDS.finiteTableEquiv : RandomSystems.DDS X Y q ≃ FiniteTableDDS X Y q` with both
`left_inv`/`right_inv` proven (no sorry); builds green. Infinite-`X` generality is
pursued only where cheap; otherwise `[Fintype X]` is assumed without apology (it is the
crypto setting). The `Fin q` form stays the computational workhorse for application proofs.
**Contrarian review PASS (2026-06-08):** length-bound is exact (table index `0..q-1` ⟺
history length `1..q` = `≠[] ∧ length ≤ q`, no off-by-one); both round-trips are genuine

Quot.sound}` — no `sorryAx`; edge cases `q=0`/empty-`X` give singleton↔singleton (sound,
not degenerate); def is fully general (no `[Fintype X]` needed). Maurer's literal
`dom ⊆ Xⁿ` (length = n) is a benign notational abuse — the Lean uses the only
prefix-closure-consistent reading (length ≤ n, his "finite-depth tree"); no deviation.
**Gated contrarian review PASS (2026-06-09):** re-verified independently — `finiteTableEquiv`

## Legend

**Kind** — `OBJ` object/type · `OP` operation/construction · `THM`
theorem/lemma/cor/fact · `NOTN` notation.

**Scope** — `★RS` pure random-systems fact (primary target) · `◆DIST` the distinguishing
/ statistical-distance primitives the RS distance theory is built on.

**Flags** — `⚠HALF` Maurer leaves it informal/partial (needs a formalization decision) ·
`⊘OMIT` proof omitted in source · `≈HAVE` analog exists in current lib (relate, don't
duplicate).

**Status** — `[ ]` todo · `[~]` stated, proof pending · `[x]` done · `[!]` **deviation**
(sound design that differs from the lecture notes — see `CR18_DEVIATIONS.md`).

**Sign-off gate.** No item is ticked (`[x]`/`[~]`/`[!]`) until it passes a **contrarian
review**: an adversarial check that the Lean is faithful to the CR18 text, that no `sorry`
hides a false statement, and that Maurer's claim is itself technically sound. If the
implementation deviates from a *correct* note → it's fixed. If the *note* is technically
wrong/incomplete → the corrected design is marked `[!]` and logged in `CR18_DEVIATIONS.md`.
